**结论先行**

- 当前 **SSE `progress` 只传 `status / done_list / running_list`**，即「哪些节点跑过」，**不传任何节点业务数据**。

### 1.3 任务状态机

| 状态 | 谁写入 | 查询任务 | 导入任务 | 是否推给前端 |
| --- | --- | --- | --- | --- |
| `pending` | `POST /upload` 响应 | 不写入 | 仅响应体返回，随后立即 `processing` | 仅上传响应，未入任务快照 |
| `processing` | `arun_query` / `arun_import` | ✅ | ✅ | 节点触发 `progress` 时携带 |
| `complete` | service 收尾 | ✅（**不推最终 progress**） | ✅（**推最终 progress**） | 查询靠前端收到 `__close__` 后本地归一 |
| `failed` | service 异常分支 | ✅ 推 `error`，不推 `__close__` | ✅ 推 `error` + `__close__` | ✅ |

前端聊天侧还有一套展示态：`idle → running → completed/failed`，由 `QueryTaskView` 在 `__close__`/error 时归一，**不以后端 `progress.status` 为准**。

### 1.4 SSE 事件契约

| 事件 | 触发方 | `data` 载荷 | 查询任务 | 导入任务 | 前端处理 |
| --- | --- | --- | --- | --- | --- |
| `ready` | `sse_generator` 建连 | `{}` | ✅ | ✅ | 无业务处理 |
| `progress` | `task_utils.task_push_sse` | `{status, done_list, running_list}` | ✅ | ✅ | 更新卡片 done/running/status |
| `delta` | `node_answer_output` | `{delta: "..."}` | ✅ 逐片 | ❌ | 追加到消息正文 |
| `final` | `node_answer_output` | `{answer: "..."}` | ✅ | ❌ | 写入最终答案 |
| `error` | service 异常分支 | `{error: "..."}` | ✅ | ✅ | 显示错误并关流 |
| `__close__` | service 收尾 | `{}` | ✅ 成功时 | ✅ 成功/失败 | 关流并归一终态 |

### 1.5 日志与追踪契约

| 项 | 现状 |
| --- | --- |
| 格式 | `time · level · file:line function · message`（`utils/logging_utils.py:10-15`） |
| 控制台 | 由 `LOG_CONSOLE_ENABLE` 控制；当前 `.env` 为 `True` |
| 文件 | 由 `LOG_FILE_ENABLE` 控制；当前 `.env` 为 `False`，默认关闭 |
| 文件路径 | `OUTPUT_DIR_LOG_DIR/app_YYYYMMDD.log`（默认 `output/logs/`） |
| 轮转/保留 | 每日 00:00 轮转，默认保留 7 天 |
| 装饰器 | `trace_node`（日志 + 任务追踪 + 可选 SSE）；`step_log`（步骤日志 + 耗时） |
| 节点计时 | `node_log` 在开始/结束各打一条，结束含 `耗时=Nms` |
| 步骤计时 | `step_log` 在开始/结束各打一条，结束含 `耗时=Nms` |
| 查询任务日志缺陷 | `QueryGraphState` 无 `task_id`，`node_log` 取 `state.get("task_id", "-")` → 节点日志里的 `task_id` 恒为 `-`；真实追踪 ID 只在 `_task_trace` 中使用 `session_id` |

### 2.3 两类任务的关键差异

| 差异点 | 查询任务 | 导入任务 | 影响 |
| --- | --- | --- | --- |
| 任务标识 | `session_id` | 独立 `task_id` | 同会话并发查询会共享进度与 SSE 队列 |
| 终态推送 | 不推 `complete` 快照 | 推 `complete` 快照 | 查询卡片终态由前端自行归一 |
| 任务结果 | 无 | `result=ok` | 无法从后端查询「这次查询产出了什么」 |
| 并行分支 | 三路检索并行 | md 压缩包按文件扇出 | 导入 done 列表会去重，分支不可区分 |
| 失败收尾 | `error` 后不推 `__close__` | `error` + `__close__` | 查询依赖前端收到 error 后主动关流 |

## 4. 导入任务：逐节点可观测数据

### 4.1 流程与节点总表

入口按文件类型分叉：`pdf → PDF 转 Markdown`、`markdown → 处理 Markdown 独文件`、`markdown-zip → 处理 Markdown 压缩包`；三条链路汇入 `node_md_tail` 子图（`markdown 图片识别 → 文档切分 → 文档嵌入入库`）。压缩包会按 md 文件数 `Send` 扇出，**每个 md 一条独立分支**。

| 顺序 | 节点函数 | 显示名（SSE） | 输入 state | 输出 state | 外部副作用 | 代码位置 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `node_entry` | 识别文档类别 | `origin_file_path` | `origin_file_type`、`file_title` | 无 | `import_processor/nodes/node_entry.py` |
| 2a | `node_pdf_to_md` | PDF 转 Markdown | `origin_file_path`、`file_title` | `markdown_file_path` | MinerU + 磁盘 | `node_pdf_to_md.py` |
| 2b | `node_process_standalone_md` | 处理 Markdown 独文件 | `origin_file_path`、`file_title` | `markdown_file_path` | 下载图片 + 磁盘 | `node_process_standalone_md.py` |
| 2c | `node_process_md_zip` | 处理 Markdown 压缩包 | `origin_file_path`、`file_title` | `markdown_file_paths`、`markdown_file_path`（单 md） | 解压 + 图片归拢 + 磁盘 | `node_process_md_zip.py` |
| 3 | `node_md_img` | Markdown 图片识别 | `markdown_file_path`、`file_title` | `markdown_file_path`（`_fixed.md`） | VLM + MinIO + 磁盘 | `node_md_img.py` |

### 6.3 建议的统一节点事件（非现状）

> 仅作为 P2 接口设计参考，当前代码没有该结构。

```json
{
  "task_id": "…",
  "task_type": "query",
  "node": "意图识别",
  "node_key": "node_intent_recognize",
  "seq": 3,
  "status": "done",
  "started_at": "2026-10-25T10:00:00.000+08:00",
  "cost_ms": 1834,
  "summary": "重写查询并确认 2 篇文档",
  "data": {
    "rewritten_query": "…",
    "confirm_list": [
      { "doc_id": 7, "title": "万用表RS-12的使用", "score": 0.91 }
    ],
    "suspect_list": [],
    "recall_count": 5
  },
  "artifacts": [{ "type": "doc", "doc_id": 7 }],
  "error": null
}
```

设计要点：

- `progress` 保留现有 `done/running/status`，新增 `node_events` 或逐节点事件，避免破坏现有前端。
- 所有大文本（prompt、重排全文、chunk 全文）只放摘要/截断，完整内容落项目文件或对象存储。
- `summary` 面向 UI 单行展示；`data` 面向详情展开；`artifacts` 面向跳转。
- `node_key` 与 `node` 同时存在，兼容现网中文展示名。
