## 3. 关键实现

### 3.1 数据与 store

- `queryTask: QueryTaskView | null` 常驻、仅内存，不持久化；页面渲染时只有 `queryTask` 非空才挂载 `QueryTaskBar`。
- `send`：`id = makeId("task")`；一次性写入 user/bot 消息（bot 无 progress）与 `queryTask`（`pending`，空步骤），`sending = true`。新查询直接顶替旧任务。
- `progress`：只 `patchTask({ done, running, status })`，不再写 `messages`；旧 SSE 不再污染新任务。
- `final`：写答案、`typing/streaming = false`、`sending = false`；**不清任务**，等待 `__close__`。
- `__close__`：`finishTask(id, "completed")`；卡片随 `status` 自动收起。同时也释放 `sending`（见 §4.2）。
- `error` / 断连：`finishTask(finalReceived ? "completed" : "failed")`，`sending = false`；错误文本仍写入 bot 消息。
- `postQuery` 失败：`finishTask("failed")`（无步骤），bot 消息 `error` 分支展示错误。
- `clearHistory`：`queryTask = null`；卡片卸载，高水位归零。
- 终态归一：`progress.status` 写为 `completed / failed`，摘要不再出现「全部完成却显示处理中」。

### 3.2 唯一卡片与自动收起

```text
send            → queryTask.pending        → 卡片挂载，open=true（展开）
progress(...)   → done/running/status 更新 → 卡片内容刷新；用户手动收起后不被强行改回
final           → 答案写入，任务保留       → 卡片仍展开，等 __close__
__close__       → status=completed         → open=false 自动收起为摘要行
error / 失败    → status=failed            → open=false 自动收起为摘要行
send（下一次）  → 新 task.id               → QueryProgress 重挂载，open=true 重新展开
clearHistory    → queryTask=null           → 卡片卸载
```

- `QueryProgress` 的 `key={task.id}` 让新任务内容重置；`open` 只在 prop 真正变化时由 React 写 DOM，因此运行中用户手动展开/收起后，后续进度刷新不会强制改回。
- 箭头沿用 `details.progress summary::before` 现有样式：收起 `>`、展开 `v`。
- `StatusLog` 的摘要改为 ReactNode 仅为「标题 / 计数」拆分，导入页 `summary` 字符串调用不受影响。

### 3.3 停靠区结构与几何

```text
.composer-wrap
└─ .composer-anchor（display:flex; flex-direction:column）
   ├─ .task-slot（display:flow-root，含卡片 8px 下边距）
   │  └─ .task-bar（width:calc(100% - 108px); margin:0 auto 8px）
   │     └─ details.progress
   └─ .composer-dock（position:relative）
      ├─ .scroll-to-bottom（right:11px; bottom:calc(100% + 10px)）
      └─ .composer
```

- `.task-slot` 用 `flow-root` 撑住卡片的 8px 下边距：实测 `slot.offsetHeight = card.offsetHeight + 8`。
- `.scroll-to-bottom` 的定位上下文改为 `.composer-dock`（= 输入卡），卡片高度变化不会移动按钮。
- 实测几何（Light/Dark 一致）：

| 视口 | 卡片宽 | 输入卡宽 | 左右内缩 | 卡片右缘-按钮左缘 | 按钮右缘-输入卡右缘 | 卡片-输入卡间距 |

- 390 下摘要自动两行：标题保持单行，计数独占一行（`summary` 高 40px）；三个视口均无横向滚动。
- `.composer-wrap::before` 高度改为 `max(140px, 100%)`，随停靠区增长，覆盖卡片 + 输入卡。

### 3.4 高水位与滚动（R2.1 核心）

- 卡片在停靠区流内，手动收起会缩短 `paddingBottom`，浏览器把 `scrollTop` 夹到新的最大值 → 列表视觉偏移。
- 修复：`cardHighWater = max(cardHighWater, cardH)`，手动展开只增、手动收起不减；留白 = `composerH + 28 + cardHighWater`。收起后保留占位空白，`scrollTop` 不变。
- `ChatComposer` 用 `ResizeObserver` 观察 `.composer-anchor` / `.task-slot` / `.composer`；`composerH = anchorH - cardH`，只有 `composerH` 变化（输入卡打字/换行、窗口尺寸变化）才 `follow=true` → `keepBottom()`；卡片自动/手动展开收起均为 `follow=false`。
- 高水位重置放在 `useLayoutEffect`（而非普通 `useEffect`）：React 的 layout effect 先于浏览器渲染步骤里的 `ResizeObserver` 回调执行，能保证「终态先归零 → 自动收起后的高度重建高水位」的顺序，避免沿用展开态的旧高水位。
- 新查询 / 清空：`queryTask?.id` 变化 → 高水位归零，由新卡片重新积累。
- 终态：`status` 变为 completed/failed → 高水位先归零；原本贴底（`pinnedRef`）则 `scrollToBottom()`，卡片收起后的高度回调把高水位重建为收起高度，留白收缩，跟到答案。
- Activity 防重：`<Activity>` 切回会重新执行 page 的 layout effect。用 ref 记录「已处理的任务 id / 终态」，只有 id 或 status 真正变化才重置高水位；否则手动收起后切 Tab 回来会把留白缩回收起高度、`scrollTop` 被钳制（`ResizeObserver` 重建为收起高度）。

### 3.5 消息区清理

- `ChatMessage` 删除 `progress` 字段；`welcomeMessage` / `historyToMessages` / `send` / 错误分支不再构造进度。
- `MessageBubble` 只保留 typing / error / answer；页面任意时刻 `.chat-inner .progress` 数量为 0。

## 4. 实现说明 / 与设计的细微偏差

### 4.1 旧 SSE 校验使用请求级任务 id

设计写的是「旧 SSE 一律按任务 `id` 校验」。实现中把请求 token（模块级 `activeTaskId`）与卡片状态 `queryTask` 分开：

- **cards/任务更新**仍校验 `queryTask.id`（`patchTask` / `finishTask`）；
- **请求级状态**（`sending`、消息收尾）校验 `activeTaskId`。

原因：设计明确「运行中清空历史 → 清卡片，SSE 仍跑完」。若所有回调都只看 `queryTask.id`，清空后 `queryTask` 为 `null`，`final/__close__` 会被当成旧流忽略，`sending` 永久为 true，发送按钮再也无法恢复。分开后：清空只影响卡片，流结束仍能释放 `sending`，且新查询会替换 `activeTaskId`，旧流不会污染新任务。

### 4.2 `__close__` 同时释放 `sending`

正常时序是 `final → __close__`，`final` 已置 `sending=false`。额外在 `__close__` 置一次，是为了在 `final` 丢失/极端断流时序下不把发送按钮永久锁死；有 `activeTaskId` 守卫，旧任务的 close 不会误释放新请求。

### 4.3 `useLayoutEffect` 重置高水位

设计示例使用 `useEffect`；实现改为 `useLayoutEffect`，让高水位重置先于 ResizeObserver 回调执行，保证终态收起后按收起高度重建、新查询不沿用旧卡片的高水位。`follow` 逻辑仍只在输入卡高度变化时贴底。

### 4.4 未改动的部分

- `StatusIcon`、`lib/sse.ts`、`lib/api/*`、`types/app.ts`、`lib/constants.ts`、导入页、`docsStore`、后端 `src/**` 均未改。
- 未做 P2（详细跟踪/失败详情）、P3（中止任务）、消息区历史进度。
