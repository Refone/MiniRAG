## 1. 验收（实现后逐条核对）

1. **单卡片**：页面只有输入框上方一个 `.task-bar`；消息区不出现 `.progress`；删除 `ChatMessage.progress`。
2. **常驻/顶替**：卡片显示最后一次查询；完成/失败后保留并**自动收起为摘要行**；新查询原地顶替并展开；`clearHistory` 清卡片；刷新不恢复（不持久化）。
3. **布局**：卡片与输入框同中线，`width: calc(100% - 108px)`（1280 660px / 390 262px），左右各 54px，与输入框间距 8px。
4. **吸底按钮**：32px，`right: 11px`，位于 `.composer-dock` 内、输入卡上方 10px；卡片右缘到按钮左缘 = 11px = 按钮右缘到输入框右缘 11px；卡片展开/收起**不移动按钮**。
5. **滚动偏移**：卡片创建后，手动展开/收起不改变 `chat.scrollTop`（高水位）；只有输入卡自身高度变化才贴底。
6. **终态**：`__close__` / error 收尾；卡片自动收起；高水位重置为收起高度；原本贴底时跟到答案。
7. **箭头**：收起 `>`、展开 `v`（沿用 `details.progress` 现有样式）。
8. **不引入**：P2 中止链路、导入页改动、后端改动、消息区逐条进度历史。

## 2. 数据与 store

```ts
// types/chat.ts
export interface QueryTaskView {
  id: string;              // 任务实例 id：隔离旧 SSE，也是卡片内容重置 key
  progress: ProgressView;
}
// ChatMessage：删除 progress 字段
```

`chatStore` 增加 `queryTask: QueryTaskView | null`（常驻、仅内存）：

- `send`：`id = makeId("task")`；追加 user/bot 消息（bot 无 progress）；`queryTask = task`；`sending = true`。
- `progress`：`patchTask(id, { done, running, status })`；**不写 messages**。
- `final`：写答案、`typing/streaming=false`、`sending=false`；**不清任务**。
- `__close__`：`finishTask(id, "completed")`；卡片自动收起；只有 `clearHistory` / 新 `send` 会清或换任务。
- `error` / 断连：`finishTask(id, finalReceived ? "completed" : "failed")`；`sending=false`。
- `postQuery` 失败：`finishTask(id, "failed")`（无步骤）；bot 消息 `error`。
- `clearHistory`：`queryTask = null`。
- 旧 SSE 一律按任务 `id` 校验；`sending` 是请求级状态，极端并发不在 P1 处理范围。
- **状态归一**：终态把 `progress.status` 写为 `completed / failed`，修掉「已完成 6/6 却显示处理中」。

**`MessageBubble`**：删除 `ProgressDetails`、进度分支及相关 import；只保留 typing / error / answer。
**`welcomeMessage` / `historyToMessages` / `send` / 错误分支**：删除所有 `progress` 字段构造。

## 4. 关键实现

### 4.1 卡片组件

```tsx
// QueryTaskBar.tsx
export function QueryTaskBar({ task }: { task: QueryTaskView }) {
  const isRunning =
    task.progress.status === "pending" || task.progress.status === "processing";
  return (
    <div className="task-bar" role="status" aria-live="polite"
         aria-atomic="false" aria-label="查询任务状态">
      <QueryProgress key={task.id} progress={task.progress} open={isRunning} />
    </div>
  );
}

// QueryProgress.tsx
export function QueryProgress({ progress, open }: { progress: ProgressView; open: boolean }) {
  const status = PROGRESS_STATUS_LABELS[progress.status] || progress.status || "unknown";
  const lines: StatusLogLine[] = [
    ...progress.done.map((text) => ({ kind: "done" as const, text })),
    ...progress.running.map((text) => ({ kind: "running" as const, text })),
  ];
  return (
    <StatusLog className="progress" open={open}
      summary={<>
        <span className="progress-title">阶段进度</span>
        <span className="progress-count">
          （已完成{progress.done.length}，进行中{progress.running.length}，状态：{status}）
        </span>
      </>}
      lines={lines}
    />
  );
}
```

- 终态 `open=false` 自动收起；`key={task.id}` 让新任务重新展开。用户手动展开后，后续进度重渲染不会强制改回（React 只在 `open` prop 变化时写属性）。
- `StatusLog` 的 `summary` 用 ReactNode 仅为「标题/计数」拆分；导入页仍传字符串。
- 箭头不在新 CSS 里实现：沿用 `chat.css` 现有 `details.progress summary::before`（收起 `>`、展开 `v`）。

### 4.3 高度、高水位与滚动（R2.1 核心）

- **问题**：卡片在流内，手动收起会让 anchor 变矮、`paddingBottom` 缩短；列表接近底部时浏览器把 `scrollTop` 夹到新最大值，列表偏移。
- **修复**：卡片高度用**高水位** `cardHighWater = max(cardHighWater, cardH)`；手动展开只增，手动收起不减。留白 = `composerH + 28 + cardHighWater`。
- **重置**：新查询（`queryTask.id` 变化）→ 0；终态 → 先归零，等卡片自动收起后的高度回调重建，再（原本贴底时）跟答案；`clearHistory` → 0。
- **follow**：只有输入卡自身高度变化才 `keepBottom()`；卡片变化、手动展开/收起都不滚动。
- 卡片高度 `cardH` 含卡片自身高度 + 8px 外边距；`anchorH - cardH = composerH`。

```tsx
// ChatPage
const cardHighWaterRef = useRef(0);
const status = queryTask?.progress.status;

const handleHeightChange = useCallback((anchorH: number, cardH: number, follow: boolean) => {
  const el = chatRef.current;
  if (!el) return;
  cardHighWaterRef.current = Math.max(cardHighWaterRef.current, cardH);
  const composerH = anchorH - cardH;
  el.style.paddingBottom = `${composerH + 28 + cardHighWaterRef.current}px`;
  if (follow) keepBottom();
}, [keepBottom]);

// 新查询：高水位归零，由新卡片重新积累
useEffect(() => { cardHighWaterRef.current = 0; }, [queryTask?.id]);

// 终态：先归零，让自动收起后的卡片高度重建高水位；原本贴底时跟到答案
useEffect(() => {
  if (status !== "completed" && status !== "failed") return;
  cardHighWaterRef.current = 0;
  if (pinnedRef.current) scrollToBottom();
}, [status, scrollToBottom, pinnedRef]);
```

`ChatComposer`：

- `statusSlot` 外包 `.task-slot`（ref），测量 `cardH = taskSlot.offsetHeight`（含 8）；
- 同时测量 `.composer-anchor` 总高 `anchorH`；
- `ResizeObserver`：composer 自身高度变化 → `follow=true`；仅卡片/停靠区变化 → `follow=false`；
- 回调 `onHeightChange(anchorH, cardH, follow)`；按钮保留在 `.composer-dock`。

### 4.4 状态机/时序

```text
idle(无卡片) --send--> running(卡片展开) --progress--> running
                          ├─ final --> finishing(等最后一条 progress)
                          │              └─ __close__ --> completed(卡片常驻+自动收起)
                          ├─ error/断连 --> failed(常驻+自动收起)
                          └─ postQuery 失败 --> failed(常驻+自动收起, 无步骤)
completed/failed --send--> running(内容顶替+展开, 高水位归零)
completed/failed --手动展开摘要--> 展开(仅 UI, 不改任务; 高水位增大)
任意 --clearHistory--> idle(卡片卸载, 高水位归零)
```

- 终态顺序：状态归一 → 卡片 `open=false` 收起 → 高水位重置为收起高度 → 更新留白 → 原本贴底则 `scrollToBottom()`。
- 后端不推 `COMPLETE`；必须以 `__close__` 收尾，不能以 `final` 或 `progress.status=completed` 清任务/卡片。

## 7. 边界/已知取舍

| 项 | 说明 |
| --- | --- |
| 手动收起后的空白 | 高水位保留原占位，是「scrollTop 不变」的直接代价；新查询归零（落地后终态不自动收起，收起后空白保留到新查询） |
| 刷新 | `queryTask` 仅内存，刷新后无卡片；历史不带进度 |
| 只显示最后一次任务 | 更早查询没有逐条进度（R1 要求）；需要时后续 Phase 再做任务历史 |
| 失败卡片 | 无步骤，摘要显示失败；错误文本在消息内；失败详情留待后续 Phase |
| 运行中清空历史 | 清卡片，SSE 仍跑完；任务中止见 P2 |
| 旧 SSE | 任务 id 校验；`sending` 极端竞态沿用现状，后续 Phase 再收口 |
| 窄屏 | 390 卡片 262；摘要「标题一行 + 计数一行」 |
| 完成态 | 常驻（落地后保持展开，可手动收起/关闭），直到新查询或清空 |
