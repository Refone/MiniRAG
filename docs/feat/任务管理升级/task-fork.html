ZIP 任务分叉

原型说明 · 非产品 UI

解压校验
原型演示

ZIP 上传不再只显示一张“压缩包任务卡”。在解压与 md 校验完成、扇出每个 md 的 tail 之前， 后端为每篇 md 分配独立的子任务标识；前端据此 fork 出各自的进度卡片， 每张卡片独立更新步骤、耗时与失败归因。

1 个 压缩包任务 → fork → md 1 md 2 md 3 md 4
1
fork 时机

解压、清理 macOS 垃圾、路径越界校验、md 去重全部通过之后；此时才知道真实的 md 列表，且尚未开始任何 tail 节点。

2
独立身份

父任务继续使用原 task_id（Milvus / MinIO 语义不变），子任务用 child_id 作为进度命名空间；父进度仍走 progress，子进度走新增的 child-progress 事件，同一条 SSE 通道。

3
独立终态

每个 md 的 tail（图片识别 → 文档切分 → 文档嵌入入库）独立完成或失败；父卡片只保留压缩包级步骤与聚合进度，不再出现“某一步已完成但别的 md 还在跑”的串台。
