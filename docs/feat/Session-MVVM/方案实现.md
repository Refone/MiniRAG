> 本文档记录 Session-MVVM V0 的实际实施内容与验证结果，并预留 Bug 追踪章节（§6）供后续问题提出与修复跟踪使用。

## 1. 实施概述

按方案设计-V0.md §6 的实施顺序完成 V0 全部六步：

1. `App.tsx` 双 `<Activity>` 保活（React 19.3，`@types/react` 19.3.0 类型可用）；
2. 安装 `zustand@5.0.16`，新增 `requestCache.ts` / `imageCache.ts`，`PreviewMode` 移入 `types.ts`，`api.ts` 收敛 4 个 HTTP 函数；
3. chatStore + ChatPage 改造（SSE 上移，页面改订阅）；
4. docsStore + ImportPage 改造（上传 SSE 上移，失效点收敛）；
5. `Markdown.tsx` 图片走 `useImageUrl`；后端 `/api/files` 加 `Cache-Control`；
6. zustand persist 配置（partialize 白名单 + version 1）。

## 3. 核心实现点

### 3.1 保活与 effects 守卫

- 两页常驻 `<Activity>`：隐藏页 `display:none`，state 与 DOM 保留（滚动位置、输入草稿、预览模式、左滑视图等视觉状态零代码保留）；**不做"记录偏移 + 事后滑动"**（测试反馈 #4 机制说明）；
- Activity 切回 `visible` 会**重建 effects**，因此相关 effect 必须加守卫：
  - ChatPage 滚动：`useScrollRestore`（贴底跟随模式 `pinnedRef`）——贴底时发送/流式跟随到底，上翻阅读后不强制滚动，切回恢复原位置（paint 前恢复，无跳动）；
  - 文档列表 / 预览 / 上传列表：`useScrollRestore` 各自独立保存/恢复，互不联动；切回后重算 ChunkRail 高亮；
  - ImportPage ChunkRail：`prevSelKeyRef` 守卫，仅真正切换文档/预览模式时重置高亮；
  - 图标动画：`CompleteIcon` / `FailedIcon` `onAnimationEnd` 后定格，避免 `display:none → visible` 时 CSS 动画重播（BUG-001）。

### 3.2 SSE 上移（任务跟踪）

- 查询流：`chatStore` 模块级 `esRef`，`send()` 内建连，progress/delta/final/`__close__`/error 回调写 store；页面切走/隐藏/卸载均不 close；
- 上传流：`docsStore` 模块级 `esMap: Record<fileId, EventSource>`，`uploadFiles()` → `postUpload` → `startSse()`；完成回调 `updateFile(completed)` + `invalidateCache("docs:list")` + 去重后自动刷新列表；
- 页面内原"卸载关闭 SSE"的 cleanup 已删除。

### 3.3 请求缓存与失效

- key 约定：`docs:list`（TTL 30s）、`docs:detail:{docId}`（TTL 5min）、`history:{sessionId}`（TTL 30s）；
- 失效点（收敛在 store 动作内）：上传完成 → `docs:list`；删除 → `docs:list` + `docs:detail:{docId}`；清历史 → `history:{sessionId}`；
- 竞态保护：`selectDoc` 快速连选时校验 `selectedId === docId` 才落详情。

### 3.4 图片缓存

- 站内判定：`/api/files/**` 或 `API_BASE + /api/files/**`；外部 http(s) 原样渲染（受第三方缓存头限制，已知边界）；
- `useImageUrl`：命中直接返回 objectURL；未命中先按原 URL 渲染，后台 fetch→blob→objectURL 就绪后切换（并发去重，失败静默回退）；同一 URL 重复 effect 保留既有 objectURL，防止闪回（BUG-002）；
- **封顶跳过、不淘汰**：会话内存 300 条 / 300MB 封顶，满后新图直接走原 URL；已缓存条目绝不 revoke（`<Activity>` 隐藏销毁 effects 会使引用计数误判，淘汰会破坏仍挂载的 `<img>`）；
- 后端 `Cache-Control: public, max-age=86400, immutable` 兜底跨刷新场景。

### 3.5 持久化

- `kb-chat-store`：partialize `{ enableWebSearch, enableHyde }`，version 1；
- `kb-docs-store`：partialize `{ previewMode }`，version 1；
- `sessionId` 沿用 `kb_session_id`（现状机制，未迁移）。

### 6.2 记录明细

#### BUG-001：会话页任务完成/失败 icon 切回 Tab 后动画重复播放

- **状态**：已修复；**发现日期**：2026-10-22；**环境**：dev（localhost:5173），Chrome
- **现象**：切回会话页时，已完成的阶段进度 icon 重新播放绘制动画
- **复现**：提问 → 等待「已完成」icon 动画播完 → 切文档页 → 切回会话页
- **期望**：完成 icon 保持定格，不重播；**实际**：动画从头重播
- **根因**：CSS 动画在子树经历 `display:none → visible` 时重新播放（`<Activity>` 隐藏即 `display:none`）
- **修复**：`CompleteIcon` / `FailedIcon` 增加 `onAnimationEnd` → 定格最终状态（inline `animation: none` + `strokeDashoffset: 0`）。涉及 `web/src/components/CompleteIcon.tsx`、`FailedIcon.tsx`
- **验证**：待浏览器验证；**关联**：测试反馈.md #2、设计 §8-1

#### BUG-002：切回会话页图片重新请求 / 渲染闪烁

- **状态**：已修复；**发现日期**：2026-10-22；**环境**：dev（localhost:5173），Chrome
- **现象**：切回会话页时站内图片间歇性重新请求，已渲染图片偶发闪烁
- **复现**：会话页渲染出 `/api/files/**` 图片 → 切文档页 → 切回，观察 Network 与图片区域
- **期望**：会话内站内图片零重复请求、无闪烁；**实际**：间歇性重新请求 + 闪一下
- **根因**：① 初版 imageCache 带 LRU 淘汰 + revoke + 引用计数；`<Activity>` 隐藏销毁 effects 使引用计数误降为 0 → 淘汰并 revoke 仍被 DOM 中 `<img>` 引用的 blob URL → 切回断裂、回退原 URL 重拉；② 未命中分支无条件清空 objectURL，闪回原 URL；③ 进度更新触发整条 markdown 重解析。外部图片不受前端控制，属已知边界
- **修复**：① imageCache 改为封顶跳过、绝不淘汰（300 条 / 300MB，满后新图走原 URL）；② 未命中时保留同一 URL 上一次的 objectURL；③ `MarkdownContent` / `MessageBubble` memo 剪枝。涉及 `web/src/lib/imageCache.ts`、`web/src/components/Markdown.tsx`、`web/src/pages/ChatPage.tsx`
- **验证**：待浏览器验证（站内图片切回零请求）；**关联**：测试反馈.md #2/#4、设计 §5.3、§8-2

#### BUG-003：五个列表切换 Tab 滚动漂移

- **状态**：已修复；**发现日期**：2026-10-22；**环境**：dev（localhost:5173），Chrome
- **现象**：切换 Tab 后会话列表与预览页滚动位置漂移
- **复现**：会话列表上翻到中部 → 切文档页 → 切回；预览页滚到中部 → 切对话页 → 切回
- **期望**：五个列表（会话 / 预览原文 / 切块 / 特征 / 上传页）彼此独立、各自保持；**实际**：位置漂移
- **机制说明**：DOM 由 `<Activity>` 完整保留（"完整渲染常驻"方案，非"记录偏移 + 事后滑动"）；列表之间无联动关系。漂移源于浏览器可能重置 `display:none` 容器的 scrollTop
- **修复**：新增 `useScrollRestore`——持续被动记录 scrollTop（含贴底判定），切回 visible 时于 paint 前（`useLayoutEffect`）恢复，无可见跳动；应用于 `.chat` / `.doc-list-scroll` / `.preview-scroll` / `.import-body` 四个容器；恢复后重算 ChunkRail 高亮。涉及 `web/src/lib/scrollRestore.ts`（新增）、`web/src/pages/ChatPage.tsx`、`web/src/pages/ImportPage.tsx`
- **验证**：待浏览器验证；**关联**：测试反馈.md #4、本文 §3.1

#### BUG-004：click / message handler 长耗时（~600ms）

- **状态**：已修复；**发现日期**：2026-10-22；**环境**：dev（localhost:5173），Chrome DevTools [Violation] 日志
- **现象**：`'click' handler took 595ms`、`'message' handler took 565ms`
- **复现**：正常使用中观察 DevTools Violation 日志
- **期望**：handler 耗时在可接受范围；**实际**：数百毫秒级长任务
- **根因**：两页常驻后，① 每次进度/流式更新触发整条 markdown 重解析与无关消息/条目的重渲染；② Tab 切换的 display 提交覆盖大 DOM 子树
- **修复**：渲染剪枝——`MarkdownContent`、`MessageBubble`、`DocItem`、`ImportTaskItem` 均 memo，未变化子树跳过重渲染。若仍明显，下一步按调研 R4 做隐藏期订阅裁剪。涉及 `web/src/components/Markdown.tsx`、`web/src/pages/ChatPage.tsx`、`web/src/pages/ImportPage.tsx`
- **验证**：待浏览器验证（Violation 日志是否消失/降低）；**关联**：测试反馈.md #3、调研 R4、设计 §5.4
