# Session-MVVM 方案设计（V0）

> 依据：[PRD-V0.md](./PRD-V0.md)（需求）＋ [方案调研-V0.md](./方案调研-V0.md)（选型，已采纳）
> 本文档说明：架构调整、改动点清单（文件级）、核心状态（变量）定义、关键机制设计与实施顺序。

---

## 1. 设计目标与范围

### 1.1 V0 目标

1. 对话 ⇄ 文档管理两个 Tab 自由切换，**不丢失任何交互状态**（滚动位置、预览模式、导入中间态、输入草稿）；
2. 切 Tab 后**图片不重新请求**、会话不跳回末尾、文档页右侧不回到缺省页；
3. **processing 任务（查询流式、上传进度）在切 Tab 后仍持续跟踪**（PRD 最痛点）；
4. 框架预留 tokens 消耗、统一任务运行状态等 session-global 状态。

### 1.2 非目标（V1 及以后，设计上留挂载点）

- 刷新页面后恢复流式进度（SSE 断点重连）；
- 图片跨刷新持久缓存（IndexedDB）；
- 跨浏览器 Tab/窗口同步（BroadcastChannel 等）；
- tokens 计费视图、统一任务状态视图的实现。

## 2. 总体架构调整

### 2.1 现状 vs 目标

```
【现状】                                 【目标】
App.tsx                                  App.tsx（page 状态 + <Activity> 双保活）
 ├─ NavBar                                ├─ NavBar
 └─ {page==="chat" ? <ChatPage/>          └─ <Activity mode>── ChatPage ──┐
     : <ImportPage/>}                     └─ <Activity mode>── ImportPage ┘
                                            （两页常驻；隐藏页 display:none，
状态：全部 useState 在页面组件内；             state/DOM 保留，effects 销毁重建）
SSE：页面卸载时 close() → 任务失联          ┌────────────────────────────────┐
缓存：无                                    │ 会话全局层（页面隐藏/卸载无关）  │
                                            │ stores/chatStore   查询SSE+消息 │
                                            │ stores/docsStore   列表/详情/上传SSE │
                                            │ stores/sessionStore（预留）     │
                                            │ lib/requestCache  响应缓存     │
                                            │ lib/imageCache    图片Blob缓存 │
                                            └────────────────────────────────┘
```

### 2.2 四条架构调整原则

| #   | 原则                                 | 说明                                                                                                                                                     |
| --- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | **页面从"数据源"变为"视图"**         | 跨 Tab 需要共享/延续的状态全部上移到会话级 store；页面只订阅渲染 + 保留纯视觉私有状态                                                                    |
| A2  | **SSE 生命周期绑定会话，不绑定页面** | EventSource 由 store 持有，创建/关闭都不随页面走；`<Activity>` 隐藏会销毁 effects（官方语义），SSE 若留在页面里切 Tab 照样断流——这是本设计最关键的架构点 |
| A3  | **保活与上移双轨分工**               | 视觉状态（滚动、草稿、展开态）靠 Activity 零成本保留；数据/任务状态靠 store。不搞"全量状态上移+手工恢复 DOM"                                             |
| A4  | **HTTP 与缓存分层收敛**              | 所有 fetch 收敛到 `lib/api.ts`；响应复用走 `lib/requestCache.ts`；图片解码复用走 `lib/imageCache.ts`；持久化走 zustand `persist`                         |

## 4. 核心状态（变量）定义

### 4.1 `stores/chatStore.ts`

```ts
interface ChatStoreState {
  /* ---- 响应式状态 ---- */
  sessionId: string; // 初始 getSessionId()（读 localStorage kb_session_id，机制沿用现状）
  messages: ChatMessage[]; // 初始 [welcome 消息]（WELCOME_TEXT/HINT 常量迁入本文件）
  sending: boolean; // 初始 false；发送按钮 disabled 依据
  enableWebSearch: boolean; // 初始 true；persist
  enableHyde: boolean; // 初始 true；persist
  historyLoaded: boolean; // 初始 false；幂等标记（不持久化）

  /* ---- 动作 ---- */
  send: (text: string) => Promise<void>; // 校验 sending → 追加 user/bot 消息 → postQuery → 建 SSE（§5.1）
  clearHistory: () => Promise<void>; // DELETE 历史 + invalidateCache(`history:${sessionId}`) + messages 重置
  ensureHistoryLoaded: () => Promise<void>; // historyLoaded 为 false 才走 cachedGet(`history:${sessionId}`)
  setEnableWebSearch: (v: boolean) => void;
  setEnableHyde: (v: boolean) => void;
}

/* ---- 模块级（非响应式，不进 React 渲染流） ---- */
let esRef: EventSource | null = null; // 查询流连接（唯一持有者）
```

迁移对照（现 ChatPage 内部状态 → 归属）：

| 现状变量                                                           | 去向                                                                     |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| `messages / sending / sessionId / enableWebSearch / enableHyde`    | → chatStore                                                              |
| `esRef`（EventSource）                                             | → chatStore 模块级 `esRef`                                               |
| `input`                                                            | **留页面**（Activity 保留草稿；发送时作为 `send(text)` 入参）            |
| `apiConnected` + 60s 健康轮询                                      | **留页面**（隐藏时 effect 销毁、轮询暂停，恢复时重建——行为可接受且更省） |
| `chatRef/pageRef/composerRef/inputRef`、滚动/自适应/ResizeObserver | **留页面**                                                               |

### 4.2 `stores/docsStore.ts`

```ts
interface DocsStoreState {
  /* ---- 文档列表 ---- */
  docs: DocsListItem[]; // 初始 []；source of truth
  total: number; // 初始 0
  refreshing: boolean; // 初始 false（“正在刷新…”shimmer 依据）
  docsLoaded: boolean; // 初始 false；幂等标记（不持久化）

  /* ---- 右区预览 ---- */
  selectedId: string | null; // 初始 null
  detail: DocsDetailResponse | null; // 初始 null；经 requestCache 获取
  detailLoading: boolean; // 初始 false（骨架屏依据）
  previewMode: PreviewMode; // 初始 "markdown"；persist

  /* ---- 导入任务 ---- */
  files: ImportFile[]; // 初始 []；上传任务列表（SSE 进度写入）

  /* ---- toast ---- */
  toasts: ToastItem[]; // 初始 []；store 内 setTimeout 自动移除

  /* ---- 动作 ---- */
  loadDocs: (opts?: { force?: boolean }) => Promise<void>; // cachedGet("docs:list", 30s)；force 跳过缓存（“刷新”按钮）
  ensureDocsLoaded: () => void; // docsLoaded 幂等
  selectDoc: (docId: string) => Promise<void>; // cachedGet(`docs:detail:${docId}`, 5min)；失败 toast+回空
  switchMode: (mode: PreviewMode) => void; // 写 previewMode（persist 自动落 localStorage）
  resetPreview: () => void; // 清 selectedId/detail/previewMode 等（删除文档后调用）
  uploadFiles: (list: FileList | File[]) => void; // 逐文件：建 ImportFile → postUpload → 建 SSE（§5.1）
  removeDoc: (docId: string, title: string) => Promise<boolean>; // deleteDoc + 两级 invalidate + 列表/预览更新 + toast
  pushToast: (kind: ToastKind, text: string) => void;
  dismissToast: (id: number) => void;
}

/* ---- 模块级（非响应式） ---- */
const esMap: Record<string, EventSource> = {}; // fileId → 上传 SSE（唯一持有者）
const refreshedTasks = new Set<string>(); // 已完成并触发过列表刷新的 taskId（现状逻辑平移）
let toastIdSeq = 0; // toast 自增 id
```

迁移对照（现 ImportPage 内部状态 → 归属）：

| 现状变量                                                                                                            | 去向                                                                 |
| ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `docs / total / refreshing / selectedId / detail / detailLoading / previewMode / files / toasts`                    | → docsStore                                                          |
| `esRef: Record<fileId, EventSource>`、`refreshedTasksRef`、`toastIdRef`                                             | → docsStore 模块级                                                   |
| `view`（列表⇄导入左滑）                                                                                             | **留页面**（Activity 保留，切回仍在原视图）                          |
| `dragging`、`deleting`、`deletingBusy`、`railActive`、`railTip`、`railFrameRef`、`previewScrollRef`、`fileInputRef` | **留页面**（纯视觉/瞬态，保活覆盖；删除确认经 `removeDoc` 走 store） |
| `resetPreview/switchMode/selectDoc/loadDocs`                                                                        | → docsStore 同名动作                                                 |

### 4.4 持久化映射（zustand persist + partialize）

| store     | persist name    | partialize 白名单                 | version |
| --------- | --------------- | --------------------------------- | ------- |
| chatStore | `kb-chat-store` | `{ enableWebSearch, enableHyde }` | 1       |
| docsStore | `kb-docs-store` | `{ previewMode }`                 | 1       |

原则：**只持久化小而稳定的 UI 偏好**。`messages / detail / files` 等大数据不进 localStorage（同步序列化卡 UI、配额风险）；sessionId 继续沿用现有 `kb_session_id` 键，不迁移。V1 加字段时升 version + 写 migrate。

### 4.5 PRD 状态清单 → 具体落点明细

本节回答"**哪些东西被缓存/保存 → 落到哪个文件哪个变量 → 用什么方式 → 关键代码在哪**"。

先明确载体与数据库边界：

- 本次前端复用的全部载体只有四种：**① 浏览器内存（JS 模块变量/Map）② localStorage ③ 浏览器 HTTP 缓存 ④ 页面 DOM（保活）**；
- **不引入任何数据库（含 Redis）**——理由见 [方案调研-V0.md §2.3.2](./方案调研-V0.md)；
- 后端现状存储（不属于本次缓存层，仅澄清）：聊天历史 → MongoDB `chat_history` collection；任务运行状态 → 后端进程内存（`src/utils/task_utils.py` 的 defaultdict，进程重启即失）；图片/文档制品 → MinIO。

#### 4.5.1 服务端响应数据（requestCache 内存 Map + store 渲染快照）

| 状态项   | 缓存的具体内容                                                                    | 落点（文件 → 变量/键）                                                                                                                                  | 缓存方式                                                                                         | 关键代码位置                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文档列表 | `GET /api/docs` 的完整响应 `{total, list}`                                        | `web/src/lib/requestCache.ts` 模块级 `dataCache: Map<string, {data, ts}>`，key=`docs:list`；渲染快照另存 `docsStore.docs / total`                       | `cachedGet("docs:list", …, {ttlMs: 30_000})`：TTL 内命中直接返回；并发去重共享 in-flight Promise | 实现：`requestCache.ts` 的 `cachedGet()`；调用方：`docsStore.loadDocs()`；失效：`uploadFiles()` 完成回调、`removeDoc()` 内 `invalidateCache("docs:list")` |
| 文档详情 | `GET /api/docs/{doc_id}` 完整响应（title/markdown_text/chunks/keywords/abstract） | `requestCache.ts` 模块级 `dataCache`，key=`docs:detail:{docId}`；渲染快照另存 `docsStore.detail`                                                        | `cachedGet(…, {ttlMs: 300_000})`（内容不可变，TTL 只是安全网）                                   | 调用方：`docsStore.selectDoc()`；失效：`removeDoc()` 内 `invalidateCache("docs:detail:" + docId)`                                                         |
| 聊天历史 | `GET /api/history/{sessionId}` 的 `history: HistoryItem[]`                        | `requestCache.ts` 模块级 `dataCache`，key=`history:{sessionId}`；转换后的展示态另存 `chatStore.messages`（welcome + 历史消息，含旧版图片 URL 兼容转换） | `cachedGet(…, {ttlMs: 30_000})`；`historyLoaded` 布尔保证一个会话只拉一次                        | 调用方：`chatStore.ensureHistoryLoaded()`（App 挂载时触发，幂等）；失效：`chatStore.clearHistory()` 内 `invalidateCache("history:" + sessionId)`          |

> 双份关系说明：`dataCache` 是**原始响应**缓存（供重复挂载/并发复用），store 里的 `docs/detail/messages` 是**渲染快照**（驱动视图）；两者通过 store 动作保持同步，页面组件不直接碰 `dataCache`。

#### 4.5.2 图片二进制（imageCache 内存 Map + HTTP 缓存兜底）

| 状态项                           | 缓存的具体内容                                       | 落点（文件 → 变量）                                                                                     | 缓存方式                                                                                                                                                                                                                                                           | 关键代码位置                                                                                                                                                  |
| -------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话页图片缓存（session global） | 图片二进制（`Blob`）及其 `objectURL`（解码结果复用） | `web/src/lib/imageCache.ts` 模块级 `imageMap: Map<url, {objectUrl, bytes, lastUsed}>`（**浏览器内存**） | `getImageUrl(url)`：站内 `/api/files/**`（或 `API_BASE` 前缀形态）→ `fetch → blob → URL.createObjectURL` 入缓存；命中直接返回 objectURL；LRU 上限 200 条 / 200MB，淘汰时 `URL.revokeObjectURL`；fetch 失败回退原 URL。外部 `http(s)` URL 不入此缓存（多数无 CORS） | 实现：`imageCache.ts` 的 `getImageUrl()`；消费点：`web/src/components/Markdown.tsx` 的 `img` 组件 `src={getImageUrl(src)}`（ChatPage 与 ImportPage 预览共用） |
| 预览区图片缓存（session global） | 同上                                                 | 同上（同一 `imageMap`，两页共用）                                                                       | 同上                                                                                                                                                                                                                                                               | 同上                                                                                                                                                          |
| 跨刷新兜底                       | 图片 HTTP 响应体（浏览器磁盘缓存）                   | 浏览器 HTTP 缓存（非 JS 变量）                                                                          | 后端 `src/api/main.py` 的 `get_file()` 响应加 `Cache-Control: public, max-age=86400, immutable`（MinIO 对象无覆盖写，长缓存安全）                                                                                                                                  | 后端一行改动：`StreamingResponse(..., headers={"Cache-Control": …})`                                                                                          |

#### 4.5.3 视觉/DOM 状态（Activity 保活 → 无变量、无文件改动）

| 状态项                                                    | 保存的具体内容                                            | 落点                                                                                                                                          | 方式                                                                    | 关键代码位置                                                                             |
| --------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 会话 cursor（滚动位置）                                   | `.chat` 容器的 DOM `scrollTop`                            | 页面 DOM（无 JS 变量）                                                                                                                        | `<Activity mode>` 保活：隐藏时 `display:none`、DOM 不销毁，切回原样恢复 | `web/src/App.tsx` 的 `<Activity mode={page==="chat" ? …}>`（唯一改动点，页面本身零改动） |
| 文档列表滚动、预览区 cursor（滚动）                       | `.doc-list-scroll` / `.preview-scroll` 的 DOM `scrollTop` | 页面 DOM（无 JS 变量）                                                                                                                        | 同上                                                                    | 同上                                                                                     |
| 输入草稿、view 左滑位置、拖拽态、删除弹窗、ChunkRail 高亮 | 页面组件 `useState` 值（React state 由 Activity 保留）    | `web/src/pages/ChatPage.tsx` 的 `input`；`web/src/pages/ImportPage.tsx` 的 `view / dragging / deleting / deletingBusy / railActive / railTip` | 保活保留 React state（隐藏时 effects 销毁但 state 不丢）                | 页面内 `useState` 声明处（现状不动）                                                     |

> 生命周期：本组全部为**会话内**（刷新页面后重建，PRD 可接受）；分页 cursor 字段（V1 分页化）预留在 `chatStore`/`docsStore` 中，见 4.5.6。

#### 4.5.4 任务跟踪（SSE 连接 + 进度状态，session global）

| 状态项           | 保存的具体内容                                                                                | 落点（文件 → 变量）                                                                                                                              | 方式                                                                                                   | 关键代码位置                                                                      |
| ---------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 查询任务（流式） | ① EventSource 连接；② 阶段进度 `done/running/status`；③ 流式文本                              | ① `web/src/stores/chatStore.ts` 模块级 `esRef: EventSource \| null`；②③ 写入 `chatStore.messages[i].progress / .text`                            | 连接生命周期=会话（页面切走/隐藏/卸载均不 close）；`final`/`__close__`/`error` 后 close 并置空 `esRef` | `chatStore.send()`（建连、progress/delta/final/`__close__`/error 回调全部在此）   |
| 上传任务         | ① EventSource 连接（fileId → ES）；② 每文件 `status/done/running/startedAt`；③ 已刷新去重标记 | ① `web/src/stores/docsStore.ts` 模块级 `esMap: Record<string, EventSource>`；② 写入 `docsStore.files[i]`；③ 模块级 `refreshedTasks: Set<string>` | 同上；`complete` → `updateFile(completed)` + `invalidateCache("docs:list")` + 去重后 `loadDocs()`      | `docsStore.uploadFiles()`（建条目、POST 上传）与 `startSseStream()`（建连与回调） |

> 刷新页面后连接会断（V0 明示边界）；V1 重连的挂载点：`sessionStore.tasks`（见 4.5.6）。

#### 4.5.5 持久化偏好（localStorage）

| 状态项               | 保存的具体内容                          | 落点（localStorage 键）               | 方式                                    | 关键代码位置                                                          |
| -------------------- | --------------------------------------- | ------------------------------------- | --------------------------------------- | --------------------------------------------------------------------- |

## 5. 关键机制设计

### 5.1 SSE 任务上移（核心）

**查询流（chatStore.send）时序**：

```
send(text)
 ├─ 校验 sending → set sending=true
 ├─ 追加 userMsg + botMsg(typing/streaming=true)
 ├─ postQuery(payload) ──失败→ 补 error 到 botMsg，sending=false，结束
 ├─ es = new EventSource(`/api/query/sse/${session_id}`)；esRef = es
 │    progress → updateMessage(botId, { progress })；completed → typing=false
 │    delta    → rawAnswer += delta（闭包变量，不进 state）→ updateMessage(botId, { text })
 │    final    → updateMessage(botId, { text: answer || rawAnswer, streaming:false })
 │    __close__ → updateMessage(streaming:false) → es.close()（不在此刻置 sending，保持现状语义）
 │    error    → 补错误文本 → es.close() → sending=false
 └─（连接由 store 持有：页面切走/隐藏/卸载均不 close）
```

**上传流（docsStore.uploadFiles）时序**：沿用现状两步式，仅宿主迁移——`postUpload(File)` → `task_id` → `startSse(taskId, fileId)` 建 EventSource 入 `esMap`；`progress` 写 `updateFile`；`complete` → `updateFile(completed)` + `invalidateCache("docs:list")` + 去重后 `pushToast` + `loadDocs()`；`__close__` → close 并 `delete esMap[fileId]`；`error` → 非终态则标记 error。

**幂等与 StrictMode**：store 是模块级单例，不受组件双挂载影响；仅 `ensureHistoryLoaded`/`ensureDocsLoaded` 由 App 的 `useEffect` 触发，靠布尔标记天然幂等。同一 sessionId/taskId 绝不重复建 EventSource（`esRef` 存在即复用）。

### 5.2 请求缓存与失效流

- 实现：`cachedGet(key, fetcher, { ttlMs, force })` —— Map 存 `{data, ts}`，进行中 Promise 去重（并发共享），TTL 过期重取；`invalidateCache(prefix)` 按前缀清除。
- key 约定：`docs:list` / `docs:detail:{docId}` / `history:{sessionId}`。
- TTL：`docs:list` 30s（多浏览器 Tab 改动的安全网）；`docs:detail:*` 5min（内容不可变，删除即失效）；`history:*` 30s（多 Tab 同会话对话的安全网）。
- 失效点收敛为 3 处，全部发生在 store 动作内：

```
上传完成 ──→ invalidateCache("docs:list") ──→ loadDocs()
删除文档 ──→ invalidateCache("docs:list") + invalidateCache(`docs:detail:${docId}`)
清空历史 ──→ invalidateCache(`history:${sessionId}`)
```

### 5.3 图片缓存

**URL 形态事实**（后端契约）：markdown 内图片 URL 两种形态——站内相对路径 `/api/files/...`（占多数，经 vite proxy / nginx 同源访问）或外部 `http(s)://...`；历史数据可能存在 `API_BASE + /api/files/...` 绝对形态。

```
getImageUrl(url)
 ├─ 命中 Map<url, objectUrl> → 直接返回（含 LRU 刷新）
 ├─ 站内判定：url 以 "/api/files/" 开头，或以 API_BASE + "/api/files/" 开头
 │    → fetch → blob → URL.createObjectURL → 入缓存 → 返回 objectUrl
 │    → fetch 失败 → 回退返回原 url（不阻塞渲染）
 └─ 外部 http(s) → 返回原 url（多数无 CORS 不可 fetch；交给浏览器 HTTP 缓存）
```

- 容量：`MAX_ENTRIES=200`、`MAX_BYTES≈200MB`，LRU 淘汰时 `URL.revokeObjectURL`；
- 消费点：`MarkdownContent` 的 `img` 组件 `src={getImageUrl(src)}`——ChatPage 与 ImportPage 预览共用，天然 session global；
- 后端配套：`/api/files` 加 `Cache-Control: public, max-age=86400, immutable`（MinIO 对象按唯一 object_name 存放、无覆盖写，长缓存安全），刷新后浏览器直接命中 HTTP 缓存不再打到 MinIO；
- dev 跨源说明：绝对形态 URL 在 dev 下指向 127.0.0.1:8000，后端已 `allow_origins=["*"]`，fetch 可行。

### 5.4 隐藏树重渲染处置（调研 R4 的落地决策）

流式 `delta` 高频更新 `messages` 时，隐藏中的 ChatPage 订阅者会被低优先级唤醒渲染。V0 决策：**接受**（两页面规模小，Activity 低优先级渲染 + 组件无重计算）；若实测卡顿，备选方案已留好——页面隐藏期间跳过 `useChatStore(selector)` 订阅（用 `page === "chat"` 条件订阅），最终态由 store 兜底。

### 5.5 页面私有状态为何不进 store

以下状态**刻意留在页面组件**：输入草稿、滚动位置、`view` 左滑位置、拖拽态、删除弹窗、ChunkRail 高亮、健康检查。理由：① Activity 隐藏/恢复时 React state 与 DOM 原样保留，零成本；② 它们无跨页面共享需求，进 store 徒增订阅与重渲染面。判断标准：**需要跨 Tab 延续且无法由 DOM 保留的（数据/连接/任务）→ store；能由 DOM/Activity 保留的（视觉/瞬态）→ 页面。**

## 8. 实施记录（V0 落地修正）

> 实施过程中对设计的三处细化，保持文档与代码一致（代码已落地于 web/src/ 与 src/api/main.py）。
