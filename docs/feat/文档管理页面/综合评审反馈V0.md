## 非阻塞提示（实现时注意，不阻碍开工）

1. **nginx 上传体积限制（发现的问题，需补进方案）**：`web/nginx.conf` 未配置 `client_max_body_size`，默认 1m——prod 下经 nginx 上传大 PDF 会被 413 拒绝。建议在 `location /api/` 增加 `client_max_body_size 64m;`（对应 `后端方案.md` §10「nginx 无需改」应补充此项）。
2. **（既存问题）SSE 经 nginx 可能被缓冲**：`web/nginx.conf` 的 `/api/` 反代未设 `proxy_buffering off`，prod 下 `/api/query/sse` 可能延迟堆积。非本次需求引入，但本次触碰部署接线，建议一并修复（如对 `/api/query/sse` 单独 location 关闭 buffering）。
3. demo-v4 中 toast 文案写的是假想端点 `GET /api/docs/{doc_id}/artifact?kind=...`，与最终方案（列表直返 `/api/files/...` 链接）不一致——demo 该文案为占位，**实现以后端方案为准**。
4. demo 的 FAKE_DOCS 里 markdown 图片是绝对地址 `http://minio:9000/...`（fake 数据）；真实数据为相对代理路径，前端无需兼容绝对地址。
5. 字段命名映射：demo 用 `file_title/file_type/docs_keywords/docs_abstract`，后端方案用 `title/type/keywords/abstract`——以 `web/src/lib/api.ts` 中类型定义为准统一，不影响接口语义。
6. demo 右上角 demo-badge（fake 标识）正式版需移除（交互评审 v0 要求，demo-v4 仍保留）。
7. 列表翻页交互未在 PRD / demo 中定义：API 提供 offset/limit+total，前端实现时确定策略（建议首期 `limit=100` 拉全或「加载更多」）。
8. NavBar 文案「文件导入」应改为「文档管理」（`web/src/App.tsx` / `web/src/components/NavBar.tsx`）。
9. `markdown_text` 对超大文档可能达 MB 级：可选启用 gzip（本地部署可不做）。
10. 删除确认弹窗文案可补充「图片」级联说明（方案 §6 已包含 `markdown-images` 清理，弹窗文案未提及，非必须）。
11. demo-v4 附带主题切换（light/dark），PRD 未要求，按需实现。
