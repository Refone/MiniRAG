## 3. 最终方案要点（后端方案.md 定稿）

| 端点 | 方法 | 职责 |
| --- | --- | --- |
| `/api/docs` | GET | 文档列表（`id:desc` 排序，offset/limit 分页，total=count(*)） |
| `/api/docs/{doc_id}` | GET | 详情：title / markdown_text / chunks[{content,level,title_stack}] / keywords / abstract |
| `/api/docs/{doc_id}` | DELETE | 级联删除：MinIO 三制品+图片 → chunks → docs 行 |
| `/api/files/{object_name}` | GET | 资源代理：stat content_type + 流式透传，四目录前缀白名单 |
| 存量端点 | — | `/api/upload`、`/api/query`、`/api/history` 等统一加 `/api` 前缀 |

- **doc_id 全程 string**（Milvus auto_id INT64 超 JS 2^53，防精度丢失）；
- **type 推导**：origin_file_url 后缀 `.pdf`→pdf，其余→markdown；
- 删除顺序与同名覆盖流程一致；`task_id` 字段保留在表中（兜底查询与溯源），仅从对象路径移除。

### 联调实测修正（3 处，已在代码注释说明）

1. Milvus 3.x 的 `order_by` 只接受冒号格式 `id:desc`（空格形式报错）；
2. `offset` 负值会触发 Milvus 报错 → 端点对 offset 做 `max(0, offset)` clamp；
3. `query_doc_by_id`/列表/计数统一 `consistency_level="Strong"`（规避删除后立刻读取的 Bounded 延迟窗口）。
