# 后端方案（已确定部分）

> 本文是「文档管理页面」后端 API 的已确定方案，基于 `后端评审v0.md` 与 demo-v4 交互定义整理。
> 尚待拍板的决策项见 [`后端评审V1.md`](./后端评审V1.md)，文中以 `V1-n` 交叉引用。
> 全部决策落定后，将本文与 V1 的结论合并，即可生成正式 `api-design.md`。

## 1. 总体设计

### 1.1 端点总览

| 端点 | 方法 | 职责 | 数据来源 |
| --- | --- | --- | --- |
| `/docs/list` | GET | 文档列表（分页） | Milvus `minirag_docs` |
| `/docs/detail/{doc_id}` | GET | 文档详情（原文 / 切块 / 关键词摘要） | Milvus `minirag_docs` + MinIO |
| `/docs/delete/{doc_id}` | DELETE | 删除文档及全部关联数据 | Milvus + MinIO |

> 端点路径沿用 `后端评审v0.md` 的命名作为占位；最终路径与 `/api` 前缀以 `V1-4` 决策为准。

### 1.2 基本原则

- **不做实时代理替换**：列表返回的链接、detail 返回的 markdown 均为入库阶段写入的原始值，后端在查询路径上不做 URL 改写。链接在浏览器中的可达性方案见 `V1-1`。
- **`doc_id` 全程字符串**：`minirag_docs.id` 是 Milvus auto_id（INT64，如 `469734951640943804`），超过 JS `Number.MAX_SAFE_INTEGER`（2^53−1），所有接口中 `doc_id` 一律以 JSON string 传输（后端 `str(id)`）。
- **错误响应**：统一 FastAPI 风格 `{"detail": "..."}`；`doc_id` 不存在时 detail / delete 返回 404。

## 2. 通用约定

### 2.1 文档类型 type 的推导

`minirag_docs` 没有类型列，按 `origin_file_url` 文件后缀推导：

| origin_file_url 后缀 | type |
| --- | --- |
| `.pdf` | `pdf` |
| `.md` / `.markdown` | `markdown` |
| 空 / 未知 | `markdown`（final markdown 制品必然存在） |

说明：markdown-zip 导入时按 md 扇出，每篇文档的 origin 制品是单个 md 文件（`node_document_embedding._derive_origin_md_path`），因此列表中的 `type` 只会出现 `pdf` 与 `markdown`，与 demo-v4 的 `file_type` 取值一致。

### 2.2 keywords / abstract 的返回格式

返回 Milvus 中入库时的原始字符串，不做拆分与改写：

- `docs_keywords`：逗号连接的原始字符串，前端按 `/[,，]/` 拆分展示（与 demo-v4「特征」页行为一致）；
- `docs_abstract`：原始字符串，可为空。

> 若 `V1-6` 决定改为后端拆分返回数组，则按 `/[,，]/` 规则拆分，其余不变。

### 2.3 排序与分页

- 列表按 `id` 降序（新文档在前，与 demo-v4 列表顺序一致）；
- 分页参数 `offset` + `limit`（默认 0 / 20，limit 上限 100）；
- `total` 通过 `count(*)` 查询获得。

## 3. GET /docs/list

### 请求

| 参数 | 位置 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `offset` | query | int | 0 | 跳过条数 |
| `limit` | query | int | 20 | 拉取条数 |

### 响应

```json
{
  "total": 6,
  "list": [
    {
      "doc_id": "469734951640943804",
      "title": "MiniRAG 架构设计文档",
      "type": "pdf",
      "pdf_link": "http://.../origin-files/.../xx.pdf",
      "chunks_link": "http://.../chunks-json/.../xx.json"
    }
  ]
}
```

- `doc_id`：string，Milvus 主键；
- `title`：`file_title`；
- `type`：推导规则见 2.1；
- `pdf_link`：`origin_file_url`，仅 type=pdf 时非空，其余为 `null`（用于「PDF」按钮新标签页预览）；
- `chunks_link`：`chunks_url`，用于「切块文件」按钮新标签页打开。

### 数据来源与查询要点

- 全部来自 `minirag_docs`；
- `output_fields` 仅取 `[id, file_title, origin_file_url, chunks_url]`，**不要**包含 `abstract_dense_vector` / `keywords_sparse_vector` 两个向量列；
- 查询参数：`filter=""`、`order_by="id desc"`、`offset` / `limit` 对应 Milvus query 的同名参数；
- 不返回 keywords / abstract / chunks 数量：按 demo-v4 列表 Item 只显示「标题 + 类型 + 按钮」（PRD 中 Item 字段的取舍见 `V1-3`）。

### 调用时机

1. 进入文档管理页面（首次）；
2. 点击「刷新」；
3. 导入任务完成后：前端轮询 `/upload/status/{task_id}` 到 `complete` 时调用（即 demo-v4 的「导入完成 → 列表自动刷新」）；
4. 上传受理成功（POST /upload 返回 202）时**不**调用——此时文档尚未入库。

## 4. GET /docs/detail/{doc_id}

### 请求

- `doc_id` 位于路径（string），无请求体。

### 响应

```json
{
  "title": "MiniRAG 架构设计文档",
  "markdown_text": "# ... 完整 markdown 原文 ...",
  "chunks": [
    {
      "content": "...",
      "level": 2,
      "title_stack": [null, "h2", "h3"]
    }
  ],
  "keywords": "MiniRAG, 架构设计, 检索",
  "abstract": "记录 MiniRAG 系统的整体设计……"
}
```

- `title`：`file_title`；
- `markdown_text`：MinIO 中 final markdown 原文**原样返回**（图片链接为入库时已替换的 MinIO 地址，不做二次代理改写；可达性见 `V1-1`）；
- `chunks`：与 chunks.json 原始结构一致 `{content, level, title_stack}`，顺序保持 chunks.json 数组顺序。demo-v4 切块卡片依赖 `level`（H1/H2/top 徽标）；`chunk_size` 不返回——demo 用 `content.length` 前端计算（ChunkRail 同源）；
- `keywords`：原始字符串（见 2.2）；
- `abstract`：原始字符串，可为空。

### 数据来源与查询要点

1. 按 `doc_id` 查 `minirag_docs` 行 → 取 `file_title / final_markdown_url / chunks_url / docs_keywords / docs_abstract`；行不存在返回 404；
2. 从 MinIO 读回 `final_markdown_url` 与 `chunks_url` 两个对象，chunks 解析为 JSON 数组；
3. MinIO 对象缺失时返回明确的错误响应（建议 404 或 500 + detail 文案）。

### 调用时机

- 点击左列表 Item（非按钮区域）时调用；进入页面不调用，右区展示空态（demo-v4 v4 变更）。

## 5. DELETE /docs/delete/{doc_id}

### 请求

- `doc_id` 位于路径（string），无请求体。

### 响应

```json
{ "success": true }
```

`doc_id` 不存在时返回 404（幂等语义的取舍见 `V1-5`）。

### 级联删除步骤（顺序）

1. 按 `doc_id` 查 `minirag_docs` 行，取 `task_id` 与 `file_title`；不存在 → 404；
2. 删除 MinIO 制品：
   - 三份制品目录：`clear_doc_artifacts(task_id, file_title)`（origin / markdown / chunks）；
   - **图片目录**：`markdown-images/{file_title}`（`node_md_img` 按 file_title 组织、不按 task_id，需一并清理，否则成孤儿对象）；
3. 删除 `minirag_chunks`：`delete_chunks_by_doc_ids([doc_id])`；
4. 删除 `minirag_docs` 行：按 `id == doc_id` 精确删除。

> 删除顺序与同名覆盖流程（`node_document_embedding.step_2_delete_old_doc`）保持一致。

### 调用时机

- 用户点击 Item「删除」并在确认弹窗中确认后调用（demo-v4 删除确认弹窗）。

## 6. 与现有实现的关系

| 能力 | 现状 | 需要新增 |
| --- | --- | --- |
| 按 id 查 docs 行 / 分页列表 / count | `milvus_client` 已有 `query_doc_rows_by_file_title` 等 | 新增 `query_doc_by_id`、分页列表与 count 查询（均指定 `output_fields` 排除向量列） |
| 删除 chunks / docs | 已有 `delete_chunks_by_doc_ids` 等 | 按 id 精确删除 docs 行的封装 |
| MinIO 读对象 | 已有上传 / 清理 | 新增 `get_object`（detail 读 markdown / chunks）与图片目录清理 |
| 上传链路 | `/upload` + `/upload/status` | 不变 |
