# V0 评审意见

1. 页面右上角 fake 数据的 UI (demo-badge) 正式版本里不要有。

2. 页面整体风格需要调整：
   1. 尽量不要出现线条或边界线，偏好使用 Elevated Card 风格。
   2. 背景不要有色彩渐变、按钮不要有色彩渐变。
   3. 与 ChatPage 风格接近，两个页面风格不要相差太大。
   4. 如果 ChatPage 违背了 1 2 两条风格，评估改动难易度，此需求可能外溢至修改 ChatPage 页面风格。

3. doc-item 太臃肿，我们把绝大部分信息放到右半区：
   1. 删除所有原文档类型标识 type-badge
   2. 删除下方所有按钮
   3. 不在 doc-item 中显示 chunks
   4. 摘要显示两行，然后…，然后再出现 展开/收起 可点击文本。
   5. 高度收紧，大概一条占现在高度一半。

4. 添加文档功能：
   1. 移除左下底部按钮，放到文档列表 (panel-header) 区域。
   2. 文档列表 / 添加文档的切换，不在是添加文档页从上往下出现，而是从左往右出现，然后从右往左收回去
   3. 文档列表的添加文档按钮，和添加文档页面的文档列表按钮，在同一个位置，方便不动鼠标来回切换。

5. 文档列表 (panel-header) 区域需要调整。现在它有几个元素：标题（文档列表/添加文档）、文档总数、刷新按钮、文档列表/添加文档切换按钮。
   1. 文档总数以小文字形式出现在标题下方：“当前文档总数: 5“，不要有括号。
   2. 刷新按钮不要用 emoji，胶囊型按钮，里面写文字”刷新“即可。点击刷新，文档总数文字变为 Shimmer 风格的“正在刷新”
   3. 切换按钮也使用胶囊型按钮。

6. 右半区-标题区 (preview-header)
   1. 文件标题位置没问题，如果原文件是 PDF，后面跟一个现在的 pdf 按钮，点击新标签预览 PDF。
   2. 在标题区移除 chunks 数量显示。chunks 信息将会在下面的 preview-body 中呈现。
   3. markdown | chunks 的切换按钮，移动到标题区最右侧，设计为一个 Text-in-Thumb Toggle 开关。

7. 右半区-页脚 (preview-footer)
   1. 整体移除，并且原本在这个位置的 markdown|chunks 切换开关也移动到了标题区。

8. 右半区-主体（preview-body)
   1. markdown 模式不用有什么大变化。
   2. chunks 显示参考 tools/markdown_chunks_viewer.html（后面简称splitter） 里面的 split 模式，我很喜欢那个风格。
   3. 参考 splitter 的 ChunkRail，在 chunks 模式最右侧也添加一条类似的 ChunkRail，用以显示切块长度分布。并且：
      1. splitter 的 Rail-Caption，我们显示 chunks 总数。例如 "total chunk: 19"
      2. splitter 是从左往右延展，我们在最右侧，因此从右往左延展，并在最右表明 chunk 编号
      3. chunk-rail 和 chunks 预览的联动也仿 splitter 来，点击 chunk-bar 有跳转，当前位置的 chunk bar 会有异色显示。
