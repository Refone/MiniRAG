# 查询兜底机制

## 现状

当前现状，在 `src/graphs/query_graph/nodes/node_intent_recognize.py` 中，如果没有文档与查询匹配，会直接回答兜底文案 "文库暂无内容与您的查询内容匹配"。
但实际还可以有更多的信息能够反馈给用户：

- 网络搜索依然可以查询
- 通过大模型回答通识型问题

## 目标

1. 在 `node_intent_recognize` 节点中如果不能找到确定的文档，不直接写回答，走到最终流程。而是依然分三路查询
   - `node_search_embedding` 和 `node_search_hyde`，空进空出，相当于节点空过（节点内判断 `state['confirm_list']` 为空提前 return 即可）。
   - `node_search_web` 通过 `state['rewritten_query']` 走网络搜索。
   - `node_rrf_and_rerank` 正常融合排序。
   - `node_answer_output` 最终整合答案的时候：
     1. 如果命中了文档，按照现在的逻辑组织回答。
     2. 如果没命中文档，需要在回答开头强调“未匹配到文库中的文档，以下是网络搜索结果/大模型直接回答结果...“（语言可润色，意图须明显）。

## 评审纪要

- 2026-11-03（测试反馈，采纳方案 A）：命中库内文档但参考内容回答不了问题时，不得直接拒答；须在回答开头声明「文库中未检索到与该问题相关的内容」，再按「网络搜索结果 → 大模型通识」的顺序兜底作答。
