## 数据链路

1. 节点在每次模型调用返回后读取 usage（LLM 取 `usage_metadata`，dashscope 取 `resp.usage`），
   累加进 graph state 的 `token_meter` 通道（`sum_token_usage` reducer）。
2. 紧接着调用 `push_usage_delta(channel_id, kind, tokens)` 推一帧 `usage-delta`。
3. service 在请求结束时 `_flush_token_usage`：读 `end_state["token_meter"]` → `TOKEN_USAGE_MANAGER.add_usage`（Mongo `$inc`）
   → `get_usage` 后推一帧 `usage` 快照。**仅成功且非空才落库+推帧**；失败路径不落库、不推、不回滚。

## SSE 契约

- 通道：查询用 `session_id`，上传用 `task_id`。
- `usage-delta`：`{"kind": "llm|vlm|embedding|reranker", "tokens": int}` —— 每次模型调用一帧。
- `usage`：`TokenUsageSnapshot` —— 请求结束前、`__close__` 之前一帧。
- 通道缓冲 `sse_channel_max_events = 2000`。

## 前端行为

- `usage-delta` → 逐个排队弹 `+N 模型` 种类气泡（不合并），chip 数字 bump。
- `usage` → 弹 `+N tokens` 总力气泡，并更新 chip / 面板数字（数字**只在请求结束更新**）。
- 面板打开时清空气泡队列，改为对应行 flash。
- Scope：会话总计 / 查询消耗 / 上传消耗。
- 失败：无总账气泡、无回滚（前端不做乐观扣减）。

## 后续修改注意

- 新增模型调用点：必须（a）把 token 累加进 `token_meter`，（b）紧邻调用 `push_usage_delta`。
  `kind` 不在 `USAGE_DELTA_KINDS` 内会被静默丢弃（前端同样按 `TOKEN_KIND_KEYS` 过滤）。
- 新增 token 种类需同步：`schema/token_usage.py`、`metering.USAGE_DELTA_KINDS`、
  Mongo `token_usage` 字段、前端 `TOKEN_KIND_KEYS` 与 `TokenPanel` 行。
- 上传通道 `task_id`、查询通道 `session_id`，不可混用。
- 统计与会话历史解耦：`session_id` 来自 localStorage `kb_session_id`，删除会话历史不影响累计。
- 答案流式调用的 usage 落在**倒数第二个 chunk**（末尾空 chunk 无 usage），改动流式解析时注意。
- 前端改动后需 `npm run build` 验证；Storybook 用例在 `TokenMeter.stories.tsx` / `TokenPanel.stories.tsx`。
