# 后端改动方案：Token 统计（v0）

> 依据：[PRD.md](./PRD.md)（正文 + 补充说明）· [demo.html](./demo.html)（交互契约）
> 状态：待评审 · 范围：四类在线大模型（LLM / VLM / Embedding / Reranker）调用的 Token 计量、按浏览器会话落库 MongoDB、查询与上传两口径拆分、读取接口与 SSE 实时刷新
> 非目标：NavBar 指示器组件与动效（前端阶段）；真实用户体系与鉴权；Token 预算 / 上限告警
> 基线：文档管理页、任务管理升级、Session-MVVM 均已落地；本方案仅新增计量与统计能力，不改动既有查询 / 导入行为

## 2. 架构调整

无。仅在既有分层内新增模块与参数：计量协议落 `common/schema`（T0）、采集器落 `common/model`（T2）、持久化落 `common/store`（T4），层间依赖方向不变，`check_layers.py` 无需调整。

数据流一句话：service 为每条查询 / 导入流构造一个 `TokenMeter`（T2，纯内存累加器）注入图状态，节点与 client 把 meter 显式传给每次模型调用；流结束（查询）或分支结束（导入）时经 `TOKEN_USAGE_MANAGER`（T4）以 Mongo `$inc` 原子落库，并向既有 SSE 通道推一帧 `usage`。

| 模型 | 位置 | 变更 | 说明 |

### 4.2 全局实例

| 实例 | 定义位置 | 变更 | 消费方 |
| --- | --- | --- | --- |
| `TOKEN_USAGE_MANAGER` | `common/store/token_usage.py` 底部，`common/store/__init__.py` re-export | 新增 | `api/main.py`（GET 端点）、`service/query_service.py`（flush + 推帧）、`graphs/import_graph.py`（分支 flush）；api 层不自行 `new` |

`TokenMeter` 不是全局单例：每条查询 / 导入流一个实例，由 service 构造注入图状态，并发流互不串数（D1）。

### 4.3 图状态 / 节点

节点链与路由均不变，仅 state 加字段：

- `QueryGraphState` 加 `token_meter: TokenMeter | None`（`_DEFAULT_STATE` 中为 None；`arun_query` 在 `create_state` 时注入实例）。节点只对 meter 对象做就地 `.record()`，不整体重赋，LangGraph 通道持同一引用，无需在返回值里回传 meter。
- `ImportGraphState` 加 `session_id: str`、`user_ip: str`、`token_meter: TokenMeter | None`。`arun_import` 注入三者；zip 扇出时 `zip_fanout_router`（`import_graph.py:134`）为每个子分支 `create_state` 传入**新的 `TokenMeter()`**，各分支独立累计、各自在 `node_md_tail_branch` 结束 flush——并发安全由 Mongo `$inc` 原子性承载。
- flush 落点统一在 `node_md_tail_branch`（`import_graph.py:71`）：PDF / 单文件 md / zip 子分支三条链路都经过该节点，上传口径在此收口；`arun_import` 不重复 flush。

### 5.1 HTTP 契约

| 端点 | 方法 | 职责 | 数据来源 |
| --- | --- | --- | --- |
| `/api/token-usage/{session_id}` | GET | 浏览器会话 Token 快照（三口径） | Mongo `token_usage` |
| `/api/upload` | POST | 上传导入（契约扩展：必填 `session_id`） | 既有端点，加表单字段 |
| `/api/query/sse/{session_id}` | GET | 查询推流（事件扩展：新增 `usage` 帧） | 既有通道 |
| `/api/upload/sse/{task_id}` | GET | 导入推流（事件扩展：新增 `usage` 帧） | 既有通道 |

#### GET /api/token-usage/{session_id}

- 请求：path `session_id`（浏览器会话标识，即前端 `localStorage kb_session_id`，`web/src/store/chatStore.ts:36-44`）。
- 响应 200（有记录）：

```json
{
  "session_id": "sess-ab12cd34",
  "user_ip": "127.0.0.1",
  "updated_at": 1751600000.0,
  "llm_tokens": 1106,
  "vlm_tokens": 1264,
  "embedding_tokens": 1795,
  "reranker_tokens": 350,
  "total_tokens": 4515,
  "query": { "llm_tokens": 620, "vlm_tokens": 0, "embedding_tokens": 905, "reranker_tokens": 350, "total_tokens": 1875 },
  "upload": { "llm_tokens": 486, "vlm_tokens": 1264, "embedding_tokens": 890, "reranker_tokens": 0, "total_tokens": 2640 }
}
```

- 无记录（demo 空统计态）：200，全 0，`updated_at: null`；不返回 404（任意 session_id 均合法，无记录 ≠ 不存在）。
- 错误：Mongo 异常 → 500 `{"detail": "Token 统计读取失败"}`（demo 统计失败态 + 重试）。store 显式抛领域异常，不复刻 `chat_history.py:83-85` 的吞异常风格（repo-map 坑 11）。
- 调用时机：NavBar 面板打开、点击重试、查询 / 上传流结束后前端刷新；失败时前端展示错误文案与重试按钮。
- 实现落点：`TOKEN_USAGE_MANAGER.get_usage(session_id)` → `find_one` + 按 D4 派生汇总。

#### POST /api/upload（改）

- multipart 表单新增：`session_id: str`（必填，浏览器会话标识），`file` 不变。
- 缺 `session_id` → 400 `{"detail": "缺少会话标识 session_id"}`（与「缺少文件名」`api/main.py:131` 风格一致）；体积超限 413、异步受理 202 行为不变。
- 实现落点：`main.py:120` 提取 `request.client.host` → `arun_import(task_id, origin_file_path, session_id, user_ip)`。

#### POST /api/query（改，契约不变）

- 请求体不变（已含 `session_id`）；handler 额外提取 `request.client.host` 传入 `arun_query`，仅服务端计量用。

#### SSE `usage` 帧（两条通道）

- `SSEEvent.USAGE = "usage"`，载荷 = `TokenUsageSnapshot` JSON。
- 查询：`arun_query` 在成功 / 失败路径 flush 后 `EVENT_BUS.push(session_id, SSEEvent.USAGE, snapshot)`，位于 `CLOSE` 之前——前端聊天流监听 `usage` 事件刷新 chip（数字跳变由前端 tween，demo 已验证）。
- 上传：`node_md_tail_branch` 每分支 flush 后 `EVENT_BUS.push(task_id, SSEEvent.USAGE, snapshot)`；zip 多分支会推多帧，前端按内容去重 / 直接取最新快照。

### 5.2 外部服务客户端

无新增外部服务、无 Redis / 队列。既有本地封装仅加可选参数：`qwen_embedding.py`、`qwen_reranker.py` 增加 `usage_sink`（缺省 None，行为与现状完全一致）；`deepseek_flash.py` 增加 `stream_usage=True`（见风险 R2）。

### 5.3 数据库 / 缓存 / 队列

| 存储 | 对象 | 变更 | 索引 | 写入时机 |
| --- | --- | --- | --- | --- |
| MongoDB | `token_usage` 集合 | 新增 | `session_id` 唯一索引（manager `__init__` 幂等创建，同 `chat_history.py:28` 模式） | 查询流结束（成功 / 失败各一次）；导入每分支结束一次；均为 `$inc` + upsert，`updated_at` 每次 `$set`，`user_ip` `$setOnInsert` |

## 6. 关键设计决策

| 编号 | 决策点 | 结论 | 理由 | 被否备选 |
| --- | --- | --- | --- | --- |
| D1 | 计量采集方式 | 协议在 T0（`schema/token_usage.py`）、采集器在 T2（`model/metering.py`）、存储 T4；节点 / client 对每次模型调用**显式传参** | 两处 `ThreadPoolExecutor`（`node_document_embedding.py:182`、`node_md_img.py:202`）会丢 contextvars；且 tier 规则禁止 model / client import store | contextvar 全局上下文（线程池漏计）；模型单例挂全局 callback（并发流互相串数） |
| D2 | usage 数据来源 | LLM / VLM 用 LangChain `usage_metadata`（invoke 直读；stream 需 `stream_usage=True`）；Embedding / Reranker 用 dashscope `resp.usage`。**取不到记 0 + WARN，不做本地估算** | `usage_metadata` 已由 `qwen3_vl_plus.py:98` 示例证实；dashscope `ReRankResponse.usage` 为 `GenerationUsage{input_tokens, output_tokens}`（SDK 源码），embedding 同源结构为 `total_tokens` | 用 `compute_token`（`utils/tokenizer.py:62`）估算兜底——与真实计费口径不一致，虚假精度 |
| D3 | 浏览器会话标识 | 沿用前端 `localStorage kb_session_id`：`/query` 已带；`/upload` 增必填表单字段，缺失 400 | 与现状零迁移成本；上传 / 查询天然落到同一会话文档，满足 R5/R6 | 后端 Set-Cookie 管理会话（引入中间件、与现有 id 双轨）；仅按 `user_ip` 聚合（NAT 共享 IP 串数、换网分裂） |
| D4 | Mongo 存储形态 | 每会话一文档 + 8 个拆分列（`query_*` / `upload_*`）；PRD 五字段在响应中派生，不冗余落库 | 单文档 `$inc` 天然原子；三口径与四模型都能一眼读出，无需聚合 | 每（会话, 口径, 模型）一行（读需聚合、并发累计变复杂）；只存 PRD 原 8 字段（无法支持三 tab 拆分） |
| D5 | 实时性 | GET 快照 + 流结束推一帧 `usage`；不做轮询；跳变动画由前端 tween | 帧数与写库次数最小、与真实刷新时机对齐；demo 的逐段跳动已被证明可纯前端实现 | 前端周期轮询（盲拉 QPS、与跳变时机脱节）；每个节点推 usage 帧（帧率高、`sse_channel_max_events` 缓冲压力，若评审要求逐阶段推送可扩为节点级 flush） |
| D6 | 落库时机与失败语义 | 查询 = 流结束（成功 / 失败都 flush，尽力而为）；上传 = 每分支结束 flush；计量失败只 WARN 不阻塞业务 | 旁路计量不拖垮主流程；失败路径已消耗的 token 也落库；zip 多分支并发由 Mongo `$inc` 原子累加 | 每节点实时写库（写放大，无业务收益）；失败不落库（与「持续统计」冲突） |
| D7 | 空态 / 错误语义 | 无记录返回 200 全 0；Mongo 读失败 500 `{"detail"}`；store 显式抛异常 | 对齐 demo 空统计 / 统计失败两个可达状态；吞异常会把读失败静默成 0 值，与 demo error 态冲突 | 无记录返回 404（空态与非法 id 混淆，前端要多写一种分支） |
| D8 | 上传口径边界 | 上传链路只计 LLM（关键词摘要）、VLM（图片识别）、Embedding（元数据 + 切片向量化）；MinerU PDF 解析不计入 | PRD L11 明确「项目中所有在线大模型调用」；MinerU 是外部文档解析服务，非大模型调用 | 把 MinerU 调用也折算 token（无 usage 依据，纯拍数） |

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| R1 | 流式 usage 依赖 `stream_usage=True`，langchain 自动开启条件不成立（`deepseek_flash.py:19` 显式传 base_url，repo-map 坑 12） | 末段 usage 缺失 → 统计漏掉答案生成的 token | 显式开启并在动工首日实测；仍取不到则该调用记 0 + WARN（D2 口径），答案生成 usage 缺失会明显可见 |
| R2 | dashscope 在线 embedding 的 `resp.usage` 字段形状 | embedding token 记 0 | SDK 批处理同源结构 `BatchTextEmbeddingUsage.total_tokens` 佐证，实现首日实测确认；异常时记 0 + WARN |
| R3 | 供应商重试 / 流式中断的已消耗 token 不随响应返回 | 统计略低于真实计费 | 诚实记 0 不估算（D2）；评审确认口径可接受 |
| R4 | `user_ip` 在 nginx 反代下取到的是网关地址 | 弱标识失真 | 仅记录展示、不做鉴权；真实 IP 需 uvicorn `proxy_headers`，超出本期 |
| R5 | 单 worker：`usage` 帧走进程内 `EVENT_BUS`，多 worker 下可能收不到 | 实时帧丢失 | 落库数据始终以 Mongo 为准（GET 兜底）；`startup_checks` 已有多 worker 告警 |
| R6 | `session_id` 是客户端明文生成的标识 | 可被伪造 / 共享 | 与 `chat_history` 同一信任模型，本期不引入鉴权（非目标） |

假设：

- A1 前后端同一需求同步上线，`/upload` 新增必填 `session_id` 无兼容窗口（旧前端调用将收到 400）。
- A2 统计以服务端为准：前端只展示 GET / SSE 快照，不自算、不上报（避免双轨计数）。
- A3 demo 的 mock 数值与 `bsess-*` 标识只是演示数据，不作为接口契约。
- A4 查询与上传共用一个 `kb_session_id`（前端现状），即两口径写入同一浏览器会话文档。
- A5 token 计数以 JSON 整数传输，量级（demo 大数值态 1,284,602）远低于 2^53，无 INT64 精度问题；本方案不新增 Milvus 主键暴露。

⏳ 未决：无。D2（缺失记 0）、D4（拆分列存储）、D5（流结束单帧）属于需要评审点头的取舍，均已给出结论与备选，不阻塞方案本身。

## 8. 实施顺序

1. 计量基座：`schema/token_usage.py` + `model/metering.py` + `store/token_usage.py` + `SSEEvent.USAGE`（纯新增、无行为变化）→ 以 `python -c` 直调 `TOKEN_USAGE_MANAGER` 验证读写。
2. 模型 / 客户端加可选参数 + `stream_usage=True`（缺省行为不变）→ 回归跑一次查询与导入确认无感。
3. 查询链路接入（state + 5 个节点 + service flush / 推帧）+ `GET /api/token-usage/{session_id}` → curl 端到端验证。
4. 导入链路接入（state + `/upload` 表单字段 + `node_md_tail_branch` flush）→ 上传 PDF 与 md zip 各一次验证。
5. 前端契约同步（`tokenUsage.ts` / `upload.ts` / 类型，前端动工阶段执行）。
6. `tools/reset_db.py` 清库重建后全流程回归。
