# 后端改动方案：Token 统计（v1）

> 依据：[PRD.md](./PRD.md)（正文 + 补充说明）· [demo.html](./demo.html)（交互契约）
> 状态：已动工 · 本版（v1）为评审要求重构后的同步稿，与当前实现一致
> 范围：四类在线大模型（LLM / VLM / Embedding / Reranker）调用的 Token 计量、按浏览器会话落库 MongoDB、查询与上传两口径拆分、读取接口与 SSE 实时刷新
> 非目标：NavBar 指示器组件与动效（前端阶段）；真实用户体系与鉴权；Token 预算 / 上限告警
> 基线：文档管理页、任务管理升级、Session-MVVM 均已落地；本方案仅新增计量与统计能力，不改动既有查询 / 导入行为

## 2. 架构调整

无。仅在既有分层内新增模块与参数：计量数据形状与 reducer 落 `common/schema`（T0）、usage 提取助手落 `common/model`（T2）、持久化落 `common/store`（T4），层间依赖方向不变，`check_layers.py` 无需调整。

数据流一句话：节点在每次模型调用后**从响应直读 usage**（LangChain `usage_metadata` / dashscope `resp.usage`），组装成本节点增量写回 `token_meter` 图状态通道（`sum_token_usage` reducer 逐字段累加）；流结束时 service 读取通道累计值，经 `TOKEN_USAGE_MANAGER`（T4）以 Mongo `$inc` 原子落库，并向既有 SSE 通道推一帧 `usage`。

## 4. 内部重要变更

### 4.1 schema

| 模型 | 位置 | 变更 | 说明 |
| --- | --- | --- | --- |
| `TokenScope` | `common/schema/token_usage.py` | 新增 | `StrEnum`：`query` / `upload`（demo 三 tab 的口径维度） |
| `TokenUsage` | 同上 | 新增 | `TypedDict` 纯数据：`llm_tokens` / `vlm_tokens` / `embedding_tokens` / `reranker_tokens`（单节点增量与通道累计值通用，可 JSON 序列化） |
| `sum_token_usage` | 同上 | 新增 | 纯函数：逐字段累加两份 `TokenUsage`，作图状态 `token_meter` 通道的 reducer；容忍 None / 缺字段 |
| `empty_token_usage` | 同上 | 新增 | 全 0 用量（图状态初始值） |
| `ModelTokenUsage` | 同上 | 新增 | pydantic：四模型 token 数 + `total_tokens` 派生 |
| `TokenUsageSnapshot` | 同上 | 新增 | 对外快照：`session_id` / `user_ip` / 三口径（总计 + `query` + `upload`）/ `updated_at` |

Mongo `token_usage` 文档示例（`_id` 由 Mongo 生成，读时不返回；`$inc` 只写非零列，零列读取时派生 0）：

  "user_ip": "127.0.0.1",
  "query_llm_tokens": 620,
  "query_vlm_tokens": 0,
  "query_embedding_tokens": 905,
  "query_reranker_tokens": 350,
  "upload_llm_tokens": 486,
  "upload_vlm_tokens": 1264,
  "upload_embedding_tokens": 890,
  "upload_reranker_tokens": 0,

PRD 的 `llm_tokens` / `vlm_tokens` / `embedding_tokens` / `reranker_tokens` / `total_tokens` 五字段不落库，在 GET 响应中由 `query_* + upload_*` 派生（D4）。

### 4.2 全局实例

| 实例 | 定义位置 | 变更 | 消费方 |
| --- | --- | --- | --- |
| `TOKEN_USAGE_MANAGER` | `common/store/token_usage.py` 底部，`common/store/__init__.py` re-export | 新增 | `api/main.py`（GET 端点）、`service/query_service.py` / `service/import_service.py`（flush + 推帧）；api 层不自行 `new` |

计量没有全局状态：节点增量走图状态通道（§4.3），service 不构造、不注入任何累加器。

### 4.3 图状态 / 节点

节点链与路由均不变，两图 state 各加一个**纯数据**字段：

- `QueryGraphState` / `ImportGraphState` 加 `token_meter: Annotated[TokenUsage, sum_token_usage]`（`_DEFAULT_STATE` 为全 0 dict，`create_state` 深拷贝即得独立初值）。
- **增量契约**：消耗 token 的节点在结束时把「本节点增量」作为 `token_meter` 写回，通道由 reducer 逐字段累加；节点**不得**返回累计值本身（会重复累加）。返回完整 state 的节点（`node_intent_recognize` / `node_answer_output`）在返回前把 `token_meter` 覆盖为本节点增量；其余节点只在返回 dict 里带该 key。
- **zip 扇出靠 reducer 折叠，无需 merge 节点 / 锁 / 共享引用**：`zip_fanout_router`（`import_graph.py:134`）的子分支 state 从 0 起算（不继承父值，避免重复计量）；`MdTailOutput` 显式回写 `token_meter`（同为 sum reducer），各分支增量回归父图时自动折叠。`_keep_latest` reducer 的存在证明 Send 扇出本身就有隐式合并点，纯数据 + reducer 恰好把「分支结果回归父流程」的诉求落到了通道机制上。
- **可序列化**：`token_meter` 是普通 dict，`save_state` / `load_state` 的 JSON 往返不受影响（此前方案里 meter 对象会让 `json.dump` 失败）。
- flush 与身份都留在 service：`arun_query` / `arun_import` 成功路径读 `end_state["token_meter"]` 落库并推 `usage` 帧；图内不碰 Mongo，state 无需携带 `session_id` / `user_ip`。

- 请求：path `session_id`（浏览器会话标识，即前端 `localStorage kb_session_id`，`web/src/store/chatStore.ts:36-44`）。
- 响应 200（有记录）：

```json
{
  "session_id": "sess-ab12cd34",
  "user_ip": "127.0.0.1",
  "updated_at": 1751600000.0,
  "llm_tokens": 1106,
  "vlm_tokens": 1264,
  "embedding_tokens": 1795,
  "reranker_tokens": 350,
  "total_tokens": 4515,
  "query": { "llm_tokens": 620, "vlm_tokens": 0, "embedding_tokens": 905, "reranker_tokens": 350, "total_tokens": 1875 },
  "upload": { "llm_tokens": 486, "vlm_tokens": 1264, "embedding_tokens": 890, "reranker_tokens": 0, "total_tokens": 2640 }
}
```

- 无记录（demo 空统计态）：200，全 0，`updated_at: null`；不返回 404（任意 session_id 均合法，无记录 ≠ 不存在）。
- 错误：Mongo 异常 → 500 `{"detail": "Token 统计读取失败"}`（demo 统计失败态 + 重试）。store 显式抛领域异常，不复刻 `chat_history.py:83-85` 的吞异常风格（repo-map 坑 11）。
- 调用时机：NavBar 面板打开、点击重试、查询 / 上传流结束后前端刷新；失败时前端展示错误文案与重试按钮。
- 实现落点：`TOKEN_USAGE_MANAGER.get_usage(session_id)` → `find_one` + 按 D4 派生汇总。

#### POST /api/upload（改）

- multipart 表单新增：`session_id: str`（必填，浏览器会话标识），`file` 不变。
- 缺 `session_id` → 400 `{"detail": "缺少会话标识 session_id"}`（与「缺少文件名」`api/main.py:131` 风格一致）；体积超限 413、异步受理 202 行为不变。
- 实现落点：`main.py:120` 提取 `request.client.host` → `arun_import(task_id, origin_file_path, session_id, user_ip)`。

#### POST /api/query（改，契约不变）

- 请求体不变（已含 `session_id`）；handler 额外提取 `request.client.host` 传入 `arun_query`，仅服务端计量用。

#### SSE `usage` 帧（两条通道）

- `SSEEvent.USAGE = "usage"`，载荷 = `TokenUsageSnapshot` JSON。
- 查询：`arun_query` 在成功路径 flush 后 `EVENT_BUS.push(session_id, SSEEvent.USAGE, snapshot)`，位于 `CLOSE` 之前——前端聊天流监听 `usage` 事件刷新 chip（数字跳变由前端 tween，demo 已验证）。
- 上传：`arun_import` 在成功路径 flush 后 `EVENT_BUS.push(task_id, SSEEvent.USAGE, snapshot)`（zip 多分支经 reducer 折叠，流结束只推一帧，前端无需去重）。

## 6. 关键设计决策

| 编号 | 决策点 | 结论 | 理由 | 被否备选 |
| --- | --- | --- | --- | --- |
| D1 | 计量采集方式 | usage **全部从模型响应直读**：LangChain `usage_metadata`（invoke 消息 / stream 末段 chunk / structured `include_raw=True` 的 raw 消息）、dashscope `resp.usage`；embedding / rerank 封装返回 `(结果, token 数)` 元组；节点组装本节点增量写回 `token_meter` 通道（`sum_token_usage` reducer） | 不注册任何回调、不注入 sink、无服务侧累加器；`token_meter` 是纯数据（可序列化），zip 分支并发由通道 reducer 折叠，天然免锁；与图状态流转语义一致 | LangChain usage callback（把非可序列化对象带进图状态 + 隐式副作用，v0 方案已被评审否掉）；contextvar 全局上下文（两处 `ThreadPoolExecutor` 漏计）；模型单例挂全局 callback（并发流串数） |
| D9 | `metering.py` 落位 | 维持 `common/model/metering.py`（T2），仅存 `message_usage_tokens` / `dashscope_total_tokens` 两个纯函数，与 `model/rate_limiter.py` 同族；不 import `common.logging`（同 tier 异子包会被 `check_layers` 拒绝），usage 缺失的 WARN 由调用节点打 | 提取助手属模型调用语义；所有消费方（graphs 节点 / client / model 封装）均可 import | `common/events/metering.py`（T3 遥测语义，合法但与 event_bus 无关、位阶更高）；并入 `schema/token_usage.py`（T0 虽允许第三方 import，但违背 schema「只定义数据约定」并把 langchain 依赖带进契约层）；`utils/`（T0 跨子包 import schema 直接违规）；新开 `common/metering/` 子包（需登记 `COMMON_TIERS`，单文件过度设计） |

## 7. 风险与未决

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| R1 | 流式 usage 依赖 `stream_usage=True`，langchain 自动开启条件不成立（`deepseek_flash.py:19` 显式传 base_url，repo-map 坑 12） | 末段 usage 缺失 → 统计漏掉答案生成的 token | 显式开启并已动工实测（全路径查询流式回答 usage 正常取到）；仍取不到则该调用记 0 + WARN（D2 口径） |
| R2 | dashscope 在线 embedding 的 `resp.usage` 字段形状 | embedding token 记 0 | SDK 批处理同源结构 `BatchTextEmbeddingUsage.total_tokens` 佐证，动工实测取到；异常时记 0 + WARN |
| R3 | 供应商重试 / 流式中断的已消耗 token 不随响应返回 | 统计略低于真实计费 | 诚实记 0 不估算（D2）；评审确认口径可接受 |
| R4 | `user_ip` 在 nginx 反代下取到的是网关地址 | 弱标识失真 | 仅记录展示、不做鉴权；真实 IP 需 uvicorn `proxy_headers`，超出本期 |
| R5 | 单 worker：`usage` 帧走进程内 `EVENT_BUS`，多 worker 下可能收不到 | 实时帧丢失 | 落库数据始终以 Mongo 为准（GET 兜底）；`startup_checks` 已有多 worker 告警 |
| R6 | `session_id` 是客户端明文生成的标识 | 可被伪造 / 共享 | 与 `chat_history` 同一信任模型，本期不引入鉴权（非目标） |
| R7 | zip 扇出子分支若继承父状态 `token_meter` 累计值，分支回归时会重复计量 | 上传消耗虚高 | 扇出 `create_state` 从 0 起算（不传父值）+ 注释约束；若未来 fork 之前出现模型调用，需重新评估该不变量 |
| R8 | 失败路径不落库（D6）：流中途失败时已消耗部分不入账 | 统计偏低于实际消耗 | 语义已在 D6 记录，待评审点头；如需保留见 D6 被否备选 |

假设：

- A1 前后端同一需求同步上线，`/upload` 新增必填 `session_id` 无兼容窗口（旧前端调用将收到 400）。
- A2 统计以服务端为准：前端只展示 GET / SSE 快照，不自算、不上报（避免双轨计数）。
- A3 demo 的 mock 数值与 `bsess-*` 标识只是演示数据，不作为接口契约。
- A4 查询与上传共用一个 `kb_session_id`（前端现状），即两口径写入同一浏览器会话文档。
- A5 token 计数以 JSON 整数传输，量级（demo 大数值态 1,284,602）远低于 2^53，无 INT64 精度问题；本方案不新增 Milvus 主键暴露。

⏳ 未决：无。D2（缺失记 0）、D4（拆分列存储）、D5（流结束单帧）、D6（失败路径不落库）属于需要评审点头的取舍，均已给出结论与备选，不阻塞方案本身。
